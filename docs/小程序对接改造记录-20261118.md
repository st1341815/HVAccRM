## 0. 一句话说明

NAS 是唯一真源，通过定时脚本**主动推送**到微信云开发；小程序只读云端。不暴露 NAS、不需要备案域名、不需要 443 端口。

```
HVAccRM (SQLite /data/crm.db)
      │  每 5 分钟：增量比对内容指纹，仅推变化的
      │  出站 HTTPS（微信云开发 HTTP API）
      ▼
微信云开发  cases（案例）+ 云存储（图片）+ visibility（展示控制）+ members（白名单）
      │  云函数（服务端权限读）
      ▼
微信小程序（列表 / 详情 / 分享卡片 / 管理）
```

## 3. 云开发侧

### 3.1 数据库集合

| 集合 | 用途 | 写入方 | 建议安全规则 |
|---|---|---|---|
| `cases` | 案例文档，一文档一案例 | 仅 NAS 同步脚本 | `{"read": false, "write": false}` |
| `members` | 内部成员 openid 白名单 | 云函数 / 控制台 | `{"read": false, "write": false}` |
| `visibility` | 案例/图片对外展示控制 | 小程序管理员（经云函数） | `{"read": false, "write": false}` |

> 三个集合对客户端全部关闭读写，所有访问都经云函数（服务端权限），暴露面最小。
> 当前数据：`cases` 12 条、`members` 1 条、`visibility` 按需产生。

### 3.2 `cases` 文档结构（NAS 推送契约）

```json
{
  "_id": "<share_token>",
  "site": "红星路96号 1栋",
  "project": "红星路96号",
  "stage": "后期施工",
  "work_date": "2026-11-08",
  "product_type": "地暖",
  "installer": "余金好",
  "cover": "cloud://<env>.<bucket>/cases/<token>/cover.jpg",
  "images": [{ "f": "cloud://.../0.jpg", "w": 810, "h": 1440 }],
  "expires_at": "",
  "disabled": false,
  "sync_ver": 1,
  "published_at": "2026-11-08T18:06:23+08:00"
}
```

**隐私红线**：`room_label`（含单元/房门）、`customer_id`、`task_id`、客户姓名电话、合同金额**永不推送**。映射表里不存在这些字段。

### 3.3 `visibility` 文档结构

```json
{
  "_id": "<share_token>",
  "visible": true,
  "hidden": ["cloud://.../3.jpg"],
  "order": ["cloud://.../2.jpg", "cloud://.../0.jpg", "..."],
  "updated_at": "2026-11-18T16:40:00.000Z",
  "updated_by": "<openid>"
}
```

- `visible=false` → 客户打开分享卡片显示「该案例暂不对外展示」（管理员仍可见）
- `hidden` → 这些 fileID 在服务端就被剔除，不下发客户端
- `order` → 自定义展示顺序，未列出的新图按原顺序追加末尾

### 3.4 云函数

| 云函数 | 职责 | 权限 |
|---|---|---|
| `whoami` | 返回 openid + 是否成员；`members` 为空时自动把首访者设为管理员 | 公开 |
| `listCases` | 分页列表 + 筛选 + 附带可见性状态 | 仅成员 |
| `getCase` | 单案例详情，应用可见性/顺序/封面替换 | 公开（凭不可枚举 token） |
| `setVisibility` | 案例开关 / 单图开关 / 图片排序 | 仅 `role=admin` 成员 |

### 4.4 新增 `scripts/wx_push.py`（容器内运行）

| 模式 | 作用 |
|---|---|
| `--sync` | **增量同步**，cron 调用 |
| `--all` | 强制全量重推 |
| `--only <token>` | 推送单个案例 |
| `--probe` | 连通性自检（token / 集合 / 开关） |
| `--dry-run` | 离线演练：字段映射 + 图片转码，不联网 |

核心机制：

- **内容指纹** = 公开字段 + 每张图 `size` + `mtime` 的 SHA1，存 `sync_state.json`
- **图片处理**：长边 1440 / JPEG q82，`convert("RGB")` 强制剥离 EXIF/GPS；另出 800×640 5:4 封面
- **写入**：`doc().set()`（本身即 upsert，删除新增兜底——实测会被 `_id` 唯一键拒绝）
- **删除清理**：本地已删案例 → `databasedelete` + `batchdeletefile`
- **限流**：单次最多 20 条 / 240 秒预算，超出留到下次
- **开关**：读 `app_settings.wx.enabled`，关闭则跳过且不删除云端数据
- **结果回写**：`wx.last_sync_at` / `wx.last_sync_result`

### 4.5 定时任务（NAS crontab）

```cron
*/5 * * * * /usr/bin/flock -n /vol1/1000/Docker/Hvaccrm/data/wx_cache/.sync.lock \
  /usr/bin/docker exec hvaccrm python /data/wx_cache/wx_push.py --sync \
  >> /vol1/1000/Docker/Hvaccrm/data/wx_cache/sync.log 2>&1
```

运行产物（`/vol1/1000/Docker/Hvaccrm/data/wx_cache/`，容器内 `/data/wx_cache/`）：

| 文件 | 说明 |
|---|---|
| `wx_push.py` | 同步脚本（可执行） |
| `wx.env` | AppID / AppSecret / EnvID，权限 **600** |
| `token.json` | access_token 缓存（提前 5 分钟续期） |
| `sync_state.json` | 12 个 token 的指纹/版本/fileID 列表 |
| `sync.log` | 同步日志 |
| `.sync.lock` | flock 锁文件 |
| `<token>/` | 转码后的图片缓存（可随时删，会自动重建） |

## 6. 部署步骤（可复现）

### 6.1 首次配置

1. 云开发控制台开通环境，记录环境 ID
2. 建集合 `cases` / `members` / `visibility`，安全规则全部 `{"read": false, "write": false}`
3. 填入 `miniprogram/config.js` 的 `cloudEnvId`
4. 服务端生成 `/data/wx_cache/wx.env`（600 权限）：

```
WX_APPID=wx9bc033a4c7d826c4
WX_SECRET=<AppSecret>
WX_ENV=cloud1-d4gv3csai7c466832
```

5. 部署云函数（开发者工具右键「上传并部署：云端安装依赖」，或 CLI）：

```bash
cli cloud functions deploy --env cloud1-d4gv3csai7c466832 \
  --names whoami listCases getCase setVisibility \
  --project <工程路径> --remote-npm-install
```

6. 后台勾选「启用定时同步」→ 保存
7. 安装 crontab（见 §4.5）

### 6.2 服务端代码生效方式

`docker-compose.yml` **未挂载** `app/` 目录，因此改后端代码有两条路：

| 方式 | 命令 | 持久性 |
|---|---|---|
| 热替换（本次采用） | `docker cp <文件> hvaccrm:/app/app/...` + `docker restart hvaccrm` | 容器重建后丢失 |
| 重建镜像（推荐固化） | `docker compose build && docker compose up -d` | 永久 |

> 本次同时更新了宿主 `app/` 源码，因此下次 `docker compose build` 会包含全部改动。
> 容器服务将在重建/升级前一直运行热替换版本。

## 9. 已知风险与待办

### 9.1 必须处理

1. **正式发布前把 `whoami` 的 `ALLOW_BOOTSTRAP` 改为 `false`**
   位置：`cloudfunctions/whoami/index.js`。否则任何打开小程序的人都可能抢占管理员。

2. **AppSecret 曾以明文出现，建议重置一次**
   公众平台 → 开发管理 → 开发设置 → 重置 AppSecret，然后更新 `/data/wx_cache/wx.env`。

3. ~~**后端改动未固化进镜像**~~
   ✅ **已解决（2026-11-18 17:06）**：随 **v1.13.0** 发版重建镜像固化。
   新镜像 `7fc8441a`，容器重建后 `/health` = `1.13.0`；回滚点 `hvaccrm:pre-1.13.0`（= v1.12.12 镜像）。
   原本用 `docker cp` 热替换的 3 个服务端文件已全部进入镜像层（`grep wx.enabled` 镜像内命中 3 处）。
   同时把 `compose_build.sh` 的回滚 tag 改成"不覆盖已存在同名 tag"——上一版就是靠这条规则才没被冲掉的。

### 9.2 需要注意

4. **云开发免费环境在发布后第 15 天到期销毁**，提审前转付费（约 19.9 元/月）
5. `data/wx_cache/wx.env` 含密钥，若进入备份包需评估；`data/wx_cache/<token>/` 是转码缓存，可定期清理

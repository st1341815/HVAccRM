## 二、维护规范（重要）

**每次发版本必须同步做两件事：**

1. 在 `app/__init__.py` 里 bump `__version__`；
2. 在本文件末尾对应的版本系列章节**追加一条记录**，格式如下：

```markdown
### vX.Y.Z（YYYY-MM-DD）

- **类型**：feat / fix / style / perf / chore / docs
- **内容**：一句话说明改了什么（功能 / bug / 视觉 / 性能 / 部署 / 文档）
```

> 一个版本号对应一次「可感知的变更」，不要一个版本号塞多件无关的事；也不要改完代码不 bump 版本号。

## 三、起源：家居建材 CRM（无版本号）

> 项目最早面向「家居建材定制行业（橱柜/衣柜/门窗）」，核心是「房号索引 + 分期收款 + 工序化交付」。
> 以下为 v0.9.0 之前完成的交付，Git 中无版本号。

- **第 1–8 轮完整交付**：楼盘/房号、客户、合同（明细/收款计划/增项）、收款、施工工序、照片、用户/角色/权限、审计、全文搜索（FTS5）等核心模块一次性搭成。
- **NAS 实测修复**：日志、权限、唯一约束修复；自检脚本可重复执行。
- **部署形态迁移**：NAS 部署改为 fnOS Compose 项目形态，补充界面管理入口与路径约定。
- **房号级联修复**：修复房号级联失效与房号静默误选。
- **部署坑记录**：补充 trim-cli 覆盖上传与 .dockerignore 两个部署坑。
- **单元白名单**：单元改为固定下拉（1~9 单元），服务端白名单校验。
- **客户表单增删字段**：新增手机/微信/意向产品，迁移 `0002`。

### v1.5.2（2026-10-27）

- **类型**：fix
- **内容**：**修复「图片曝光」埋点把未加载图片全算成已看**（v1.5.0 埋点的真实 bug，上线 10 分钟即被发现）。
  - **现象**：真实访客打开 16 图的案例，统计里 `图片曝光` 一律是 **16 / 16**，与实际只看了首屏 1~2 张不符。
  - **根因**：画廊图片带 `loading="lazy"`，加载前 `height:auto` 算出高度为 0。**零高度的 `<img>` 落在视口内时，`IntersectionObserver` 依然返回 `isIntersecting: true`（`intersectionRatio` 甚至为 1）**——于是 16 张全部「进入视口」。浏览器实测确认：`300×0` 的懒加载图返回 `isIntersecting true / ratio 1 / complete false / naturalWidth 0`。
  - **修法**：回调里增加「已真正加载」判据 —— `if (e.isIntersecting && img.complete && img.naturalWidth > 0)`。图片加载完成后高度变化会再次触发回调，**真正滑到的图仍然照常计数**，只是不再把"还没加载"的图算进去。
  - **数据订正**：该 bug 期间产生的 3 条真实访问记录（22:32~22:34）其 `viewed_images` 一律置 0（原值 16 是错的，保留反而污染平均看图）。
  - SW 缓存 `hvaccrm-shell-v46 → v47`。
- **自检**：浏览器内构造零高度懒加载图复现「误判 entering viewport」→ 应用判据后不再计入；全量 `pytest` **70 passed**（模板逻辑无改动，仅前端埋点修复）。
- **回滚点**：`hvaccrm:pre-1.5.2`（= v1.5.1 镜像）。

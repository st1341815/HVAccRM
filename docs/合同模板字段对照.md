# 合同模板 · 字段对照表

> 模板正文里写 `{{变量名}}`，打印时替换成下表的值。
> 写了**不存在的**变量不报错、不留 `{{}}`，只留空，并在打印页工具条上列出「缺哪些变量」。
> 变量清单的代码真相在 `app/services/contract_docs.py` 的 `build_context()` 与 `available_vars()`，两者必须同步。

生成日期：2026-11-25 · 对应版本 v1.14.1

## 一、合同本身的字段

| 模板里写 | 取哪里的数 | 线上现状 | 说明 |
|---|---|---|---|
| `{{合同号}}` | `contracts.no` | ✅ 11/11 有 | 例 `ONE202610250012` |
| `{{签订日}}` | `contracts.sign_date` | ✅ | `2026-10-25` |
| `{{产品类型}}` | `contracts.product_type` | ✅ 11/11 有 | 改造 / 地暖 / 暖气片 / 明装 / 锅炉 |
| `{{合同状态}}` | `contracts.status` | ✅ | `active` / `done` / `void` |
| `{{合同备注}}` | `contracts.notes` | ⚠️ **11/11 全空** | 空着纸上就是「合同备注：」一行空白，建议删这行或养成填备注的习惯 |
| `{{结算状态}}` | `contracts.settled` | ✅ | 已结算 / 未结算 |
| `{{结算日}}` | `contracts.settled_at` | — | 未结算时为空 |

## 五、表格类变量（输出整张 HTML 表）

| 模板里写 | 内容 | 线上现状 | 空表时长什么样 |
|---|---|---|---|
| `{{明细表}}` | 合同明细：产品 / 规格 / 数量 / 单位 / 单价 / 金额 + 合计 | ⚠️ **11 份合同 0 明细** | 印一行「（本合同未录入明细）」 |
| `{{收款记录}}` | 收款流水：日期 / 金额 / 方式 / 凭证号 / 收款人 / 备注 | ⚠️ 0 条 | 「（暂无收款记录）」 |
| `{{增项记录}}` | 增项：原因 / 金额 / 审批时间 | ⚠️ 0 条 | 「（无增项）」 |
| `{{成本明细}}` | 成本（**仅内部版**，客户版强制隐藏） | ⚠️ 0 条 | 「（暂无成本记录）」 |

> 明细为空是**录入习惯问题，不是 bug**：现在 11 份合同都是「整套报价 + 一个总额」
> （如「地暖 15,000」「暖气片 12,000」），没有按设备逐行录。
> 想让它出现在合同 1.5 里，得在合同详情页底部「添加明细」逐行录（可以只录一行「XX 系统 1 套 12,000」）。

## 七、怎么用得顺

1. **要改哪个字，先在模板里搜 `{{`**，看它是不是上表里的变量；不是就说明写死了，可以直接改文字。
2. **地址类只用一个**：`{{工程地点}}`。它已经包含市、区县、楼盘、楼栋、单元、房号，别在外面再拼一次。
3. **改完模板先点「预览」**，工具条会列出「模板里写了但系统给不出值」的变量名 —— 那就是你要么改名、要么去补数据。
4. **报价单/明细**：现在模板的 1.5 是「合同金额 + 优惠 + 增项 + 应收」，如果你的习惯是「空调 X 元 / 采暖 Y 元 / 新风 Z 元 / 净水 W 元」四行报价，目前系统没有这四个字段，只能：
   - 甲案：把四项当 4 条明细录进合同（`{{明细表}}` 直接出表，不用改代码）；
   - 乙案：合同表加 4 个金额字段（要改库 + 表单 + 报表口径）；
   - 丙案：保持一个总额（现状）。

## 2. 项目背景

- HVAccRM = 暖通空调 CRM，跑在飞牛 NAS 的 Docker 容器里（容器名 `hvaccrm`，映射 `8090→8000`）。
- 内网 `http://192.168.1.8:8090`，`/health` 返回 `{"status":"ok","db":true,"version":"..."}`。
- 目标：把「案例」（完工后自动生成的展示页）写成微信公众号草稿，**只存草稿、绝不自动发表**。
- 公众号是**个人主体订阅号**，无微信认证 → 无 `draft/add`/`freepublish`/JS-SDK 接口权限，所以走「容器内自跑 Chromium 操作后台」的路线。

## 5. ⚠️ 正在解决的核心问题（新会话务必先读）

### 现象（用户实测反馈，决定性证据）
```
▍工地位置颐园清苑 6栋▍施工时间2026-09-14▍施工工序后期施工▍产品类型暖气片
```
字符和 `▍` 都在，但**段落分隔全部丢失**，挤成一整行。

### 根因（已定位）
**微信保存草稿时会把多个块级元素（`<p>`/`<section>`）压平合并成一个段落。**
编辑器里 `tops=[272,315,357,400]`（分开的），存成草稿后就并成一行。

### v1.9.5 的修复方案
全部预设改为「**单个块级元素 + `<br>` 内部分段**」。
- `<br>` 是行内元素，不受块合并影响。
- 字号/颜色/粗体用 `<span>` 承载。
- 默认预设改为 `text`（最保险）。

## 7. 五条铁律（改动前必读，都是实测踩出来的坑）

1. **代码里绝不出现「发表」按钮的选择器**，只点「保存为草稿」（首次测试时坐标点击差点误发）。
2. 正文注入只能用 `execCommand('insertHTML')`；`ClipboardEvent('paste')` 会被 ProseMirror 拦掉。
3. 图片只能走 CDP `DOM.setFileInputFiles`；上传后要校验 `src` 含 `qpic.cn`（=已转存素材库，否则发表后裂图）。
4. 等图判定要「总数 + CDN 数同时达标」，只看 `cdn>=1` 会误报丢图。
5. 微信后台会弹促销弹窗（小店返佣/话题卡片），会挡住底部按钮，且有多层。

## 8. 其他关键坑（已解决，记录在 CHANGELOG）

| 坑 | 解法 |
|---|---|
| Debian 13 的 apt 永久卡死 | 必须 `-o APT::Key::UseSqv=false`（`sqv` 签名验证在无 tty 容器里挂死） |
| 不用 Playwright | `install --with-deps` 也卡死 + 多 500MB，改用 `apt-get install chromium`（381MB） |
| 容器重建后 Chromium 失效 | `SingletonLock` 记旧容器 hostname → 启动前清 `Singleton*`（`wxmp.py` 里 `_clear_stale_singleton()`） |
| 镜像体积 | 185MB → 908MB（容器内自带浏览器的代价） |

## 12. ⚠️ 2026-10-31 新增排障：「同步失败 + 公众号页面打不开」

### 现象
用户反馈两件事同时发生：① 点「同步」失败；② 点侧栏「公众号」页面打不开。

### 根因（已定位并修复）
**不是代码 bug，也不是网络故障，是容器内 Chromium 的 renderer 进程僵死。**

完整证据链：
1. 容器 15:00 重建，15:33 用户触发 `ensure_browser()` 拉起 Chromium。
2. 15:39~15:48 期间 `chrome.log` 里 Chromium 反复 `SSL handshake failed (net_error -100/-101)`——这是**飞牛 fnOS 的 DNS 分流/Fake-IP 转发层（Unbound + 198.18.0.0/15 网段）短暂抖动**所致。
3. 微信图文编辑页是重 JS 应用（ProseMirror），资源加载失败 + 反复重试 → **renderer 主线程卡死**。
4. renderer 僵死后，所有 CDP `Runtime.evaluate`（`c.js()`）全部超时——连 `1+1` 都 evaluate 不出来。
5. 于是 `login_state()` / `publish_case()` 里的 CDP 调用卡死 → 「同步失败」（note=`Connection timed out`，案例 11）+「公众号页面打不开」（`wxmp_page` 里 `login_state()` 卡在 `ensure_browser()`/`_open()`，uvicorn 单 worker 被占住）。

### 关键判断依据（复用）
- **飞牛 fnOS 会把微信域名解析到 Fake-IP**：`mp.weixin.qq.com→198.18.0.175`、`res.wx.qq.com→198.18.0.176`、`mmbiz.qpic.cn→198.18.0.184`（落在 `198.18.0.0/15` 保留段）。这是飞牛 `unbound-dnsconfd.service` + `network_service.service` 的正常设计（类似 SmartDNS Fake-IP），**平时工作正常**，证书 CN 也正确（DigiCert 签的 mp.weixin.qq.com），不是代理劫持。
- **python urllib/socket TLS 能通、Chromium 却握手失败** = 中间层抖动时 Chromium 的长连接/并发资源加载更脆弱，且失败后 renderer 不自动恢复。
- **判断 renderer 是否僵死**：`docker exec hvaccrm python3 -c "...CDP Runtime.evaluate '1+1'..."` 超时 = 僵死；能返回 = 正常。

### 修复方法（已验证，可直接复用）
```bash
# 1. 杀掉僵死的 Chromium（会留下无害的僵尸进程，不用管，容器重启自然回收）
sudo -n docker exec hvaccrm sh -c 'pkill -9 -f chromium; pkill -9 -f crashpad'
# 2. 清 Singleton 锁（否则新 Chromium 报 "profile in use"）
sudo -n docker exec hvaccrm sh -c 'rm -f /data/wxmp-profile/SingletonLock /data/wxmp-profile/SingletonCookie /data/wxmp-profile/SingletonSocket; rm -f /data/wxmp/chrome.pid'
# 3. 触发一次登录态检查，验证恢复（登录态在 profile 里，没删 profile 就不用重扫码）
sudo -n docker exec hvaccrm python3 -c "import sys; sys.path.insert(0,'/app'); from app.services import wxmp as w; w.ensure_browser(); print('token=', w._read_token(w._open()))"
```

### 教训
- **「同步失败 + 页面打不开」同时出现时，先查 renderer 是否僵死**（CDP evaluate 超时），而不是怀疑代码或网络。
- 登录态存 `/data/wxmp-profile`，只要不删 profile，杀 Chromium 重建**不需要重新扫码**。
- 飞牛 Fake-IP 转发层会偶发抖动，属平台层问题，CRM 侧无解；如频繁复发，可考虑给 Chromium 加 `--disable-http2` 或改走固定 DNS（`--host-resolver-rules`），但当前未做，先观察。
